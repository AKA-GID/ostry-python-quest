# 7.1 · Финальный рейтинг

После шести уровней квеста пора подвести итоги турнира. Сервер выдаст список участников, список раундов и записи о попытках. По этим данным составь пьедестал из трёх участников. Это финальная задача: за неё команда получает отметку о завершении, отдельного фрагмента ссылки нет.

## Входные данные

Запроси `GET /api/tasks/7.1/input`. Ответ содержит `input` с такими полями:

- `players` — участники; у каждого есть строковый `id` и имя `name`.
- `tasks` — список кодов раундов.
- `pass_score` — минимальное количество баллов за раунд, чтобы он считался решённым.
- `runs` — попытки; у каждой указаны `player_id`, `task_id`, `points` и затраченные `minutes`. Участник может иметь несколько попыток в одном раунде.

## Правила рейтинга

1. Для каждой пары «участник — раунд» выбери одну лучшую попытку: сначала с наибольшим `points`; при равенстве баллов выбери попытку с меньшим `minutes`.
2. Раунд считается решённым, если в выбранной попытке `points` не меньше `pass_score`. Раунд без попыток считается нерешённым.
3. Для каждого участника посчитай `solved` — число решённых раундов, `points` — сумму баллов только за решённые раунды, `minutes` — сумму времени только за решённые раунды.
4. Отсортируй участников: больше `solved` выше; при равенстве — больше `points`; затем меньше `minutes`; затем меньший `id` в обычном порядке строк.
5. Передай первые три места. Если участников меньше трёх, передай всех.

## Отправка ответа

Отправь `POST /api/submit`. В `answer` передай объект только с ключом `podium`: списком первых трёх участников в порядке мест. Каждая запись содержит целочисленные поля `place`, `solved`, `points`, `minutes` и строковое поле `id`.

Используй фактические значения из запроса к серверу. Ключи JSON и типы значений должны совпадать точно.
